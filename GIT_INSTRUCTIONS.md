# Git и публикация изменений проекта

Инструкция пользователя от 22 ноября 2026 года. Каждый агент обязан прочитать этот файл перед первой содержательной задачей в проекте и учитывать его при работе с Git.

## Целевой репозиторий

Все изменения проекта, включая 3D-город, в итоге должны передаваться в публичный репозиторий Жени `SHKZhenya/algorithms-kamchatka`. Целевая ветка интеграции — `main`, если пользователь явно не указал другую ветку в этом репозитории. [Репозиторий Жени](https://github.com/SHKZhenya/algorithms-kamchatka)

## Порядок передачи

1. Перед публикацией проверь актуальные ветки, remote, права доступа и состояние PR в репозитории Жени. Учитывай уже влитые изменения и работу других участников.
2. Если передача идёт через форк `Neverrie/algorithms-kamchatka`, создай PR с целевым репозиторием `SHKZhenya/algorithms-kamchatka` и целевой веткой `main`. Ветка в форке служит промежуточным этапом передачи.
3. При отчёте о публикации дай ссылку на PR или коммит именно в репозитории Жени. Укажи фактический статус — PR открыт, изменения влиты или передача заблокирована. Открытый PR означает, что интеграция ещё ожидается.
4. Если пользователь поручил довести передачу до конца, проверь появление изменений в целевой ветке. При отсутствии прав на слияние сообщи, какой PR ожидает действий владельца.

## Границы поручения

Эта инструкция определяет назначение изменений. Публикацию, push, создание PR и слияние выполняй в рамках конкретного поручения пользователя. Запрос о наличии кода или статусе переноса требует проверки и ответа. Для такого запроса сохраняй режим чтения GitHub.

Источник правила — прямое указание пользователя в чате проекта от 22 ноября 2026 года.
