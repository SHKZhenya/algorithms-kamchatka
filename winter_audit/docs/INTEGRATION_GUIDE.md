# Интеграция с snowops

Потребители сохраняют `graph_version=osm-1143744836afc553-demo-v1` и исходные ID дуг. Геометрия WGS84 в порядке [долгота, широта]. Для надежного соединения по ID разделите физический сегмент, дугу и объект обслуживания. `road_network_enriched` имеет `edge_id`, `physical_road_id` и `osm_tags`. Присоединяйте рельеф по `edge_id`, топологические флаги по `physical_road_id`, ограничения поворотов по паре `incoming,outgoing`. Между версиями OSM один логический участок может иметь несколько отображений. Исторический договор связывается по `territory_id`; геометрия кандидата не даёт исполнительского полномочия.

## Вход в ядро

1. Загрузите исходный OSM. Проверьте GraphVersion и стабилизируйте набор требований и снимок источников на `as_of`.
2. Подготовьте `RoadCondition`, `RoadEvidence` и `Capability`. Используйте `common_closures` для проецирования временных и классовых ограничений на общий список `closed_edges`. Проекция консервативно покрывает всю смену при пересечении с закрытием.
3. В режиме подрядчика примените `service_tasks` с `organization_id`. Передайте решателю только допустимые задания, удержанные возвращайте отдельно с причиной. Если все задания удержаны, сформируйте результат «планирование недоступно» до вызова ядра, где требуется непустой список. Делите вход на однородные расчёты с отдельными людьми и машинами, если ограничения различаются. Одновременную диспетчеризацию разнородного парка с индивидуальными графами текущий адаптер не выражает.
4. Вызовите исходный `GreedySolver().solve` или `PoolSolver().solve`. Ядро использует входящий переход и трафарет скоростей. После расчёта вызовите `replay`, который повторяет штатную математическую проверку, затем проверяет события в фактических интервалах действий и право выполнить каждую операцию.
5. Публикуйте прежний Plan и отдельный результат `validation_report`. `simulation_only` ядра сохраняется; `operationally_confirmed` относится только к проверенному срезу и указанному парку.

Для пилота исследовательская политика допускает выполнение расчёта при unknown и выдаёт эти случаи в отчёте. Строгая политика блокирует использование неизвестных участков. В ручном режиме внесите подтверждение с источником и интервалом. Подтверждённое техническое ограничение действует в обеих политиках. В графе транзита право на чужую уборку не проверяется.

## Frontend и координация

Используйте независимые переключатели из `frontend_layers.json`. Полигонов подтверждённых зон и объектов с рассчитанным применимым сроком в поставке нет. LineString в `responsibility_segments` означает кандидата на сопоставление. Пешеходные объекты/отрезки импортируются отдельно. Сведения о ширине, сроки и границы, для которых отсутствует доказательство, передаются как null. Геометрию защищает версия графа, сезонность определяется временными интервалами, правомерность работ — субъектом, операцией и документом. Для общегородского режима объедините результаты раздельных запусков с транспортными зависимостями. Изменение исполнителя требует зарегистрированного основания и периода.
