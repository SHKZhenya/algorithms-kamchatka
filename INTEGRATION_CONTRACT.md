# Контракт модели и планировщика · проект v0.1

Операция forecast получает состояние на момент решения и допустимый маршрут-кандидат. Планировщик формирует и проверяет допустимые маршруты. Модель прогнозирует последствия и возвращает показатели оценки. Уже начатые операции передаются в каждый пересчёт. Один и тот же идентификатор версии графа действует для всех рёбер, измерений, прогнозов и маршрутов.

| Вход | Тип и содержание |
|---|---|
| schema_version, graph_version, as_of | Строки версий, ISO 8601 UTC. Для отображения Asia/Kamchatka |
| graph | Рёбра с ID, from/to, length_m, area_m2, уклоном, классом, типом покрытия, dry_capacity_veh_h; ограничения поворотов и геометрия коридоров |
| observations[] | edge_id, observed_at, received_at, измерение с единицей, источник, качество, охват |
| initial_state[] | edge_id, s_kg_m2, i_kg_m2, bank_kg, возраст и описание совместной неопределённости |
| weather[] | issue_at, valid_from/to, snow_swe_kg_m2_h, wind_m_s и направление, cover_temp_c или air_temp_c, visibility_m и идентификатор сценария |
| fleet[], route[] | Позиция/входящее ребро, смена, возможности; vehicle_id, edge_id, mode, start_at/end_at, доля захвата или параметры действия |
| grid, constraints, costs | Горизонт, шаг отчётности, запреты, пределы обслуживания, тарифы и их единицы; версия сценарных порогов |

Расчётная сетка допускает подшаги, а изменения состояния при операциях привязаны к их завершению. Погодный интервал полуоткрытый [from,to), значения интенсивности соответствуют интервалу. Состояние на точке сетки публикуется после операций, завершающихся в этой точке. Длительности нарушений вычисляются по подшагам или событиям и сопровождаются разрешением. Сетка пилота для отчётности 5–15 мин, горизонты 30/60/120 мин. Опоздавшие наблюдения учитываются в следующей версии расчёта с трассировкой. Прогнозы и наблюдения с received_at или issue_at после as_of не используются.

| Выход | Тип и содержание |
|---|---|
| road_state[] | edge_id, valid_at, s_kg_m2, i_kg_m2, bank_kg и флаги качества |
| forecast[] | edge_id, valid_at, scenario_id, те же состояния и производные оценки |
| uncertainty | Тип интервала, квантили/сценарии с весами при наличии, покрытие при валидации и причины пропусков |
| capacity_ratio | 0..1 по ребру/коридору, Q и dry_Q [авт./ч], идентификатор метода |
| risk_proxy | Значение индекса и версия формулы, порог, длительность и тяжесть превышения, статус валидации |
| priority/constraints | Приоритеты из конфигурации, прогнозные slack и ограничения по объекту, периоду и сценарию |
| cost | Переменная стоимость по статьям и единица, отдельные фиксированные и социальные поля при наличии |
| status | ok / partial / invalid_input; для поиска отдельно feasible / no_feasible_candidate / proven_infeasible, с основанием |

Пример одной строки прогноза в сценарии:

```json
{
  "schema_version": "0.1",
  "graph_version": "demo-1",
  "as_of": "2026-11-19T00:00:00Z",
  "valid_at": "2026-11-19T01:00:00Z",
  "edge_id": "e01",
  "scenario_id": "demo-median",
  "road_state": {"s_kg_m2": 1.2, "i_kg_m2": 0.15, "bank_kg": 320},
  "uncertainty": {"kind": "scenario", "validated": false},
  "capacity_ratio": 0.78,
  "risk_proxy": {"value": 0.55, "version": "demo-1", "validated": false},
  "status": "ok"
}
```

Отсутствие данных кодируется null и причиной. Неизвестный сухой эталон делает ratio неизвестным, а подтверждённое закрытие задаёт Q = 0. Отрицательные запасы, интервалы неправильного порядка, неизвестные рёбра/единицы и разрыв пути отклоняются с указанием записи. Расчёт идентифицируется версиями графа, параметров, входов и плана. Идентичный снимок данных с фиксированным seed даёт воспроизводимый сценарный прогноз. Приведённый JSON иллюстрирует контракт; синтетический прототип запускается локально и сохраняет собственный CSV.
