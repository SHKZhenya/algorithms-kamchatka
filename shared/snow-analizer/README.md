# Карта снежных заносов

FastAPI принимает XYZ-тайл и возвращает растр оценочной толщины свежего снега на земле. Веб-интерфейс открывает тестовую застройку без сети. Для настоящего тайла контуры приходят из Overpass, а почасовые данные о ветре и осадках для центра тайла из Open-Meteo. Можно задать погоду вручную.

## Запуск

Из корня проекта, Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn snowmap.api:app --host 127.0.0.1 --port 8000
```

Откройте [карту](http://127.0.0.1:8000/) или [Swagger UI](http://127.0.0.1:8000/docs). В тестовой сцене сравните западный ветер 270° с восточным 90°. При нулевой скорости карта вне контуров домов показывает ровный слой свежего снега. Тестовые здания вымышлены. Переключатель OSM запрашивает реальную геометрию по указанным координатам.

В режиме «Интерактивная карта» перетаскивайте карту и меняйте масштаб от 15 до 20. После остановки карта рассчитывает снег для видимых тайлов. Слой снега можно отключить, а после правки ручной погоды нужно нажать «Рассчитать». Для всех видимых тайлов используется единая цветовая шкала. Верхнюю границу (30 см по умолчанию) можно изменить в поле «Максимум шкалы, см». Карта перекрашивается сразу. Значения выше выбранной границы показываются самым тёмным цветом. Режим использует локальный Leaflet при наличии и загружает подложку OpenStreetMap через интернет. Кеш зданий уменьшает число запросов к Overpass независимо от подложки.

Панель «Расчистка» в режиме «Интерактивная карта» группирует видимые здания, медучреждения и остановки по категориям. В списке указаны адрес при наличии и оценка свежего снега. Для здания с несколькими видимыми входами показывается вход с наибольшей оценкой. Порог расчистки по умолчанию составляет 20 см. Скрытие слоя снега убирает цветную заливку, а расчёт для точек продолжается.

Больницы и поликлиники из городского кеша отмечены знаком «+». Для них показывается максимальная глубина свежего снега среди доступных ячеек растра вдоль внешнего контура, отступающего от стен примерно на 5 м. Точность зависит от размера ячейки и покрытия загруженных тайлов.

- Входы загружаются из `data/building-entrance-snow.csv` или из соседнего `../stats/building-entrance-snow.csv`. Переменная `KAMCHATKA_ENTRANCE_CSV` задаёт другой путь к файлу.
- Остановки загружаются из архивов `*.osm.gz` в `data/pkc` и `weather_coverage/osm` соседнего проекта `../algorithms-kamchatka`. Переменная `KAMCHATKA_OSM_DIR` задаёт другой каталог этого проекта. Если локальный Leaflet недоступен, карта загружает его с CDN.

Данные панели доступны по `GET /clearance/points`. После обновления файлов перезапустите сервер, чтобы перечитать данные.

## API

```bash
curl -X POST http://127.0.0.1:8000/api/snow \
  -H 'Content-Type: application/json' \
  -d '{"hours":3,"manual_weather":{"wind_from_deg":270,"wind_speed_ms":8,"snowfall_cm_h":2}}'
```

Чтобы загрузить реальный тайл и прогноз, отправьте `{"tile":{"z":17,"x":123298,"y":42669},"hours":3}`. Поддерживаются уровни 15–20. Поле `resolution` задаёт число ячеек вдоль длинной стороны тайла (24–240, по умолчанию 120). `use_foam: false` включает аналитический режим для сравнения.

- `snow_depth_cm` — матрица с первой строкой на севере и первым столбцом на западе. Значения относятся к центрам ячеек. Ячейки внутри зданий имеют значение `null`.
- `bbox_wgs84` — запад, юг, восток и север. `footprints[].geometry` содержит координаты в локальных метрах к востоку и северу от юго-западного угла. В локальной системе отрисовка идёт по прямоугольному растру.
- `weather` — скорость на высоте 10 м в м/с, направление **откуда** в градусах от севера, снегопад в см и суммарные осадки в мм за расчётный час. Для прогноза `end_utc` задаёт конец часа. Ручной ввод задаёт слой снега за час, поэтому суммарные осадки в мм для него неизвестны.
- `model` — `analytic`, `hybrid` или `hybrid_partial`. `cfd_coverage` показывает долю применений шаблонов по парам «здание и уникальное состояние ветра», а `kernels_available` показывает число доступных шаблонов. `compute_ms` включает сборку растра, `total_ms` также включает работу с источниками.

Для высоты сначала используется `height`, затем `building:levels × 3 м`. При отсутствии обоих тегов берётся 9 м. Запрашиваются полигоны и мультиполигоны с запасом 360 м вокруг тайла. Зона влияния в модели ограничена 350 м по каждой оси, а в формулах дальности высота здания ограничена 45 м. В памяти одного рабочего процесса геометрия кешируется до часа, погода до пяти минут. При сбое провайдера API отвечает HTTP 502.

По умолчанию запрос идёт на `overpass-api.de`. При сетевой ошибке, тайм-ауте или временном отказе API пробует `overpass.private.coffee`. Если оба запроса завершатся ошибкой, интерфейс покажет её тип. Переменная окружения `OVERPASS_URL` задаёт единственный адрес Overpass, в том числе для собственной установки.

## Локальный кеш зданий Петропавловска-Камчатского

Из корня проекта выполните `.venv/bin/python -m snowmap.city_cache`. Команда одним POST-запросом к VK Maps Overpass загружает здания и границу OSM 4139922 и сохраняет ответ в `data/petropavlovsk-buildings.json`. Для другого сервера задайте `OVERPASS_URL`. Повторный запуск обновляет файл после проверки ответа. При ошибке прежний снимок сохраняется.

Бэкенд использует снимок для тайлов, у которых окрестность в 360 м пересекает границу города. Интерактивная карта передаёт `city_cache_only: true`, поэтому запросы зданий всегда выполняются по файлу. За пределами покрытия слой снега прозрачный. Обычный запрос отдельного тайла может обратиться к Overpass за зданиями вне покрытия. Погода загружается отдельно или задаётся вручную.

## Шаблоны OpenFOAM

В отдельном терминале, из корня проекта.

```bash
python -m snowmap.foam
```

В каталоге `kernels/` уже есть полный набор для запуска демо. Генератор запускает `blockMesh`, `simpleFoam` и `postProcess` из OpenCFD OpenFOAM. По умолчанию используется установленный в этой системе v2512. Другой путь задаётся через `--bashrc` или `OPENFOAM_BASHRC`. Для частичного набора можно повторять `--height` и `--angle`. Каталог по умолчанию — `kernels/`, изменить его для генератора и API можно через `SNOW_KERNEL_DIR`. Новые шаблоны появляются в API без перезапуска.

Для тестовой сцены при западном и восточном ветре достаточно четырёх вариантов.

```bash
python -m snowmap.foam --height 6 --height 15 --angle 0 --angle 30
```

Полный набор включает здание 24 × 12 м с высотой 6, 15 или 30 м, углы потока 0°, 30°, 60° и 90° к длинной стороне и опорную скорость 8 м/с. Симметрия прямоугольника даёт остальные квадранты. Стационарный трёхмерный расчёт RANS k–ε сохраняет отношение скорости у земли (первый слой, центр на высоте 1,5 м) к опорной скорости. API поворачивает и масштабирует шаблон по габаритам контура и интерполирует поля по высоте и углу. Высоты за пределами таблицы используют крайнюю высоту шаблона. Если для интерполяции не хватает файлов, для этого здания применяется аналитическая модель. В каждом файле записано число итераций и максимальный начальный остаток среди уравнений последнего шага. Для высоты 30 м и угла 60° использовано 500 итераций, для остальных шаблонов — 220. У варианта 30 м и 90° остаток около 0,0105, поэтому этот шаблон особенно важно проверять при инженерной калибровке.

## Реальное время и точность

Расстояние от ориентированного контура определяет короткую наветренную зону, вытянутую подветренную зону и боковые полосы со сниженным накоплением. При соседних зданиях зоны суммируются с насыщением, а перекрывающиеся боковые зоны могут снизить оценку снега в проходе. Поля OpenFOAM корректируют оценку там, где поток замедляется или ускоряется. Аэродинамическое взаимодействие групп зданий напрямую в OpenFOAM в этой версии не моделируется.

Быстрый режим обрабатывает сетку вокруг зданий, не запускает решатель и повторно использует расчёт для одинакового ветра. На этой машине при разрешении 120 и трёх разных направлениях ветра медиана расчёта четырёх зданий составила 14 мс в аналитическом режиме и 28 мс в гибридном. Для искусственной сцены из 100 зданий — 295 и 615 мс соответственно. Замеры сделаны с прогретым кешем шаблонов и без внешних запросов. Отдельный офлайн-прогон для здания 15 м при угле 0° занял 36 секунд. Время выдачи реального тайла при холодном кеше зависит от Overpass и Open-Meteo. Для городской карты с требованием гарантированной задержки потребуется локальный кеш геометрии и прогноза. Полный CFD на каждый запрос включает построение сетки, расчёт и чтение результата. Офлайн-шаблоны позволяют вынести эту работу из запроса.

Растр показывает оценку **толщины свежего снега в см**. Объёмная плотность в кг/м³ требует данных о свойствах снега. Перенос существующего снежного покрова, таяние, рельеф и баланс массы в этой версии отсутствуют. Коэффициенты модели эвристические. Для количественного прогноза нужны замеры заносов, калибровка переноса снега и проверка на группах зданий. Горизонтальная 2D-модель подходит для первичной оценки заслонения, а трёхмерный расчёт позволяет учесть поток над крышей и зависимость от высоты.

```bash
python -m unittest discover -s tests -v
```

Источники данных и описание решателя доступны в документации. [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API), [Open-Meteo](https://open-meteo.com/en/docs), [simpleFoam](https://doc.openfoam.com/2312/tools/processing/solvers/rtm/incompressible/simpleFoam/).

## Расчёт потока для выбранного тайла

Выберите «Тестовая застройка» или «Тайл OpenStreetMap», включите «Рассчитать поток в OpenFOAM», задайте погоду вручную и нажмите «Рассчитать». Для тайла OpenStreetMap галочка автоматически переключает прогноз на ручной ввод. В API тот же режим включается полем `"run_foam": true` в запросе `POST /api/snow`. Для реального тайла передайте `manual_weather`. При нулевой скорости ветра решатель пропускается.

OpenFOAM строит общую сетку по контурам зданий и рассчитывает их совместное обтекание. Заносы в этом режиме отсчитываются от отдельных фасадов реального контура, включая границы внутренних дворов. Охватывающие прямоугольники используются в быстром режиме. Расчётная область включает 90 м с каждой стороны тайла, земля плоская, верхняя граница на высоте 75 м. Горизонтальная ячейка около 6 м или крупнее на больших тайлах, вертикальная — 3 м. Высоты округляются до ближайшего вертикального шага и ограничены диапазоном 3–45 м. Контуры, в которые не попадает центр ни одной ячейки, пропускаются. Поле скорости на высоте 1,5 м корректирует эвристическую оценку накопления снега.

Для такого запроса ответ содержит `model: "openfoam_tile"` и объект `foam_run` с числом ячеек, шагом, временем расчёта и остатком. Выполняется 120 итераций. Остаток помогает оценить сходимость конкретного прогона. Запрос синхронный, а сервер принимает один такой расчёт одновременно на рабочий процесс. Одновременный запрос получает HTTP 429. Быстрый режим интерактивной карты использует шаблоны. Для установки OpenFOAM в другом каталоге задайте `OPENFOAM_BASHRC`.

## Контракт для внешней интеграции

`POST /api/snow` принимает XYZ-тайл и погоду и синхронно возвращает геопривязанный растр толщины свежего снега в сантиметрах. OpenFOAM рассчитывает шаблоны ветра офлайн.

### Геометрия и буфер

Для реального тайла достаточно передать `tile.z`, `tile.x` и `tile.y`. Контуры и теги зданий берутся из городского снимка или Overpass. Модель использует контур каждого здания для маски. В быстром режиме длина, ширина и ориентация определяются по минимальному повёрнутому прямоугольнику. В режиме расчёта тайла в OpenFOAM геометрия и зоны заносов строятся по исходным полигонам. Передача собственных полигонов через этот endpoint пока отсутствует. Готовые шаблоны хранятся на сервере.

При загрузке зданий добавляется буфер **360 м с каждой стороны тайла**. Отбор по дальности от контура здания ограничен `min(350 м, 9 × высота здания)` по каждой оси. В выходном растре остаётся только сам тайл. Влияние соседей учитывается приближённо через перекрытие зон накопления и выдувания. [Загрузка геометрии](snowmap/sources.py), [модель](snowmap/model.py).

### Высотная привязка и граничные условия

В шаблоне OpenFOAM плоская земля лежит на **z = 0 м**, верхняя граница — на **z = 60 м**. Вертикальный шаг составляет 3 м, центры слоёв лежат на 1,5; 4,5; 7,5 м и далее до 58,5 м. Онлайн используется только срез **1,5 м над землёй**. Рельеф и абсолютные высоты над уровнем моря не учитываются.

В API достаточно скорости ветра на 10 м и направления **откуда**, по часовой стрелке от севера. Профиль скорости пока отсутствует. В CFD на входе задана равномерная скорость 8 м/с, а скорость из API задаёт силу поправки на перенос снега. Для моделирования атмосферного пограничного слоя потребуется добавить профиль скорости и турбулентности.

Граничные условия генерируют функции `mesh()` и `setup()`. На входе заданы скорость и значения `k = 0,24 м²/с²`, `epsilon = 0,01 м²/с³`. На выходе задано `p = 0`, а для скорости применяется `inletOutlet`. На земле и здании заданы `noSlip` и пристеночные функции турбулентности. Верхняя и свободные боковые грани используют симметрию. [Генератор OpenFOAM](snowmap/foam.py).

### Сетка и поля OpenFOAM

Солвер использует трёхмерную гексаэдральную сетку с ячейками **3 × 3 × 3 м** в области **180 × 180 × 60 м**. Основание типового здания имеет размер 24 × 12 м. Библиотека содержит высоты 6, 15 и 30 м и углы потока 0°, 30°, 60° и 90° к длинной стороне здания.

В рабочем CFD-кейсе доступны `U = (Ux, Uy, Uz)` в м/с, `p` в м²/с², `k` в м²/с², `epsilon` в м²/с³ и `nut` в м²/с. Кинематическое давление `p` задано относительно нулевого значения на выходе. Разность давления в Па равна `ρ × Δp`, где `ρ` — плотность воздуха в кг/м³.

На диск экспортируется только матрица **60 × 60** со значениями `sqrt(Ux² + Uy²) / (8 м/с)` на высоте 1,5 м. Поля рабочего кейса удаляются после генерации. Передача полных компонент скорости, давления или турбулентности требует отдельного экспорта. [Экспорт шаблона](snowmap/foam.py).

### Высота зданий и маска

Приоритет высоты — положительный тег `height` в метрах, затем `building:levels × 3 м`, затем **9 м**. Поле `footprints[].height_source` указывает источник значения. Теги OSM принимаются без проверки на местности. Отдельный признак подтверждённой высоты отсутствует.

Маска встроена в растр. **`null`** означает, что центр ячейки попал в контур здания. **`0`** означает открытую ячейку с нулевой толщиной снега. Точные границы можно получить из `footprints`. [Парсинг высот](snowmap/sources.py), [маска](snowmap/model.py).

### Производительность и чувствительность к разрешению

Замер использует два часовых состояния ветра, 270° и 90° при 8 м/с, с 2 см снегопада за каждый час. Значения в таблице — медиана расчёта с прогретыми шаблонами, без внешних запросов и сериализации.

| Разрешение | Шаг растра на z17 | Демо, 4 здания | Городской тайл, 19 зданий с буфером |
| --- | ---: | ---: | ---: |
| 60 | ≈3,06 м | 6 мс | 18 мс |
| 120 | ≈1,53 м | 16 мс | 37 мс |
| 240 | ≈0,77 м | 66 мс | 115 мс |

При разрешении 120 один полный JSON-ответ для городского тайла занимает около **83 КБ**. Пиковый RSS процесса за весь замер составил около **110 МиБ**, включая Python, библиотеки, городской снимок и расчёт с разрешением 240. Прирост RAM на отдельный тайл не измерялся.

На городском тайле среднее по открытым ячейкам при смене разрешения составило 4,706–4,716 см, максимум — 6,765–6,769 см. При сравнении 120 и 240 средняя абсолютная разница в сопоставленных открытых ячейках составила 0,031 см, 95-й перцентиль — 0,076 см. Проверялся шаг выходного растра на двух сценах. Шаг сетки CFD оставался 3 м.

Для двух отдельных карт по направлениям используются два синхронных запроса. На городском тайле прогретый запрос с одним ручным состоянием ветра и сериализацией занимал 28–29 мс. Первый запрос в свежем процессе с загрузкой снимка занял около 393 мс. Модель умеет суммировать разные часовые состояния, но публичный API принимает одно ручное состояние на весь период. Почасовая смена ветра доступна через прогноз.

### Выходные данные о снеге

`snow_depth_cm` — оценка толщины накопившегося свежего снега в см. `forecast_snowfall_cm` — фоновый снегопад за тот же период. Их разность даёт оценку локального избытка или дефицита в см.

Входы модели — почасовое выпадение снега, ветер и геометрия зданий. Существующий снежный покров, тип поверхности, шероховатость и плотность снега не передаются. Расчёт не выдаёт поля массового потока, траектории частиц или перенос в кг/м² и кг/(м·с). Разность толщин не образует баланс массы. [Расчёт снега](snowmap/model.py).

### Пример JSON

Запрос `POST /api/snow` с `Content-Type: application/json`. Для второго направления повторите запрос с `wind_from_deg: 90`.

```json
{
  "tile": {"z": 17, "x": 123301, "y": 42693},
  "city_cache_only": true,
  "hours": 1,
  "resolution": 120,
  "use_foam": true,
  "manual_weather": {
    "wind_from_deg": 270,
    "wind_speed_ms": 8,
    "snowfall_cm_h": 2
  }
}
```

Ниже сокращённый пример формы ответа `200`. В поле `snow_depth_cm` показаны три условных значения. Полное поле содержит 120 строк по 120 значений.

```json
{
  "tile": {"z": 17, "x": 123301, "y": 42693},
  "bbox_wgs84": [158.656311, 53.004868, 158.659058, 53.006521],
  "width_m": 183.98,
  "height_m": 183.98,
  "rows": 120,
  "cols": 120,
  "geometry_source": "OpenStreetMap",
  "weather_source": "manual",
  "weather": [
    {
      "wind_from_deg": 270,
      "wind_speed_ms": 8,
      "snowfall_cm": 2,
      "precipitation_mm": null
    }
  ],
  "forecast_snowfall_cm": 2,
  "model": "hybrid",
  "cfd_coverage": 1.0,
  "max_snow_depth_cm": 3.81,
  "snow_depth_cm": [[2.0, 2.15, null]]
}
```

Порядок `bbox_wgs84` — запад, юг, восток, север. Строки растра идут с севера на юг, столбцы с запада на восток. `footprints[].geometry` использует локальные метры от юго-западного угла тайла. X направлен на восток, Y — на север.

При `city_cache_only: true` тайл вне покрытия возвращает `204` без тела, а отсутствующий или нечитаемый снимок — `503`. Для почасового прогноза опустите `manual_weather`. Для ручной погоды `precipitation_mm` возвращается как `null`, поскольку клиент задаёт толщину выпавшего снега, а суммарные осадки в миллиметрах не передаёт. [Контракт FastAPI](snowmap/api.py).
