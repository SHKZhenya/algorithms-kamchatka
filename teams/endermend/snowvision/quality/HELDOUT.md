# Отложенный архив дорожных камер

Этот протокол готовит независимую оценку, а не допуск дорожного статуса на рабочий экран. Сырые медиа, соглашения и разметку держать вне Git в частном каталоге `.quality-local` (0700), архив SQLite — 0600. До сохранения кадров получить документ с источником, разрешением на хранение и офлайн-анализ, кругом доступа и датой удаления. Не собирать медиа по умолчанию. Не публиковать URL с токенами, лица или номера без разрешения и необходимой обработки.

1. Зафиксировать идентификатор камеры, городскую зону, версию неизменного ракурса и геометрию видимой полосы. При перемещении камеры создать новую версию. Сохранить кадры через профиль `quality` с `--media-mib` только после оформления прав. Экспорт `evaluate_quality --manifest` даёт ID записей, времена и SHA-256 PNG. Проверить происхождение времени съёмки: `source`, `http_last_modified` либо `unknown`; время получения хранить отдельно. Метка HTTP не доказывает точное время съёмки.
2. Присвоить единый `episode_id` всем камерам и кадрам одного метеоэпизода, включая отрицательные интервалы до/после. Заранее назначить `tune` или `test` целому эпизоду. Для одной камеры между разделами оставить более 90 минут; одинаковый PNG нельзя делить между ними. Не выбирать тест по результатам модели. Нужны независимые эпизоды, разные условия света и ракурсы для проверки переноса.
3. Два разметчика независимо фиксируют осадки (`none`, `rain`, `snow`, `mixed`, `unknown`), пригодность обзора воздуха и полосы (`good`, `limited`, `unusable`), покрытие **размеченной видимой полосы** (`clear`, `partial`, `covered`, `unknown`) и нормализованный многоугольник полосы для определённого покрытия. Споры разрешаются отдельным решением (`resolved`); согласие — `agreed`. При сомнении использовать `unknown`. Для `mixed` указать `snow_present`, только если наличие снега достоверно. Не превращать покрытие видимой части в статус всей дороги.
4. Создать JSON по [схеме-примеру](manifest.example.json), сверив `sample_id`, `frame_sha256`, `view_revision` и `received_at` с архивом. Запустить проверку и затем офлайн-сравнение **только test**:

```sh
export SNOWVISION_PILOT_DIR="$PWD/.quality-local"
docker compose -p snowvision run --rm --no-deps --user "$(id -u):$(id -g)" --entrypoint python quality -m snowvision.cli.heldout_dataset /pilot/archive.db /pilot/heldout.json
docker compose -p snowvision run --rm --no-deps --user "$(id -u):$(id -g)" --entrypoint python quality -m snowvision.cli.evaluate_quality /pilot/archive.db --heldout /pilot/heldout.json > .quality-local/heldout-report.json
```

В отчёте сравниваются `recorded`, `opencv_replay` и `shadow` на одних размеченных кадрах. `weather_vlm_v2` появляется только при явно разрешённом `--scene-url`; модель и версия промпта записываются в отчёт. Оценка начала эпизода требует отдельной полной разметки интервалов; эти метрики не следует выводить из единичных кадров. До наличия независимых test-эпизодов и оценки области полосы дорожный статус остаётся вне рабочего экрана.
