# Контекст фронтенда SnowVision

План следующего изменения: [главный экран для пилота с диспетчером](UI_UX_PILOT_TASK.md).
Три приоритета заказчика — текущий снегопад, погода и штормовое предупреждение,
до трёх камер по реальному вкладу в оценку. Это задание, а не выполненный редизайн.

Код находится в `teams/endermend/snowvision/frontend`. React и TypeScript собираются Vite, nginx обслуживает приложение и проксирует `/api`.

## Модули

Функции камер, оповещений и городской сводки лежат в `src/features` вместе с тестами.

- frontend/src/main.tsx: монтирование React и подключение стилей.
- frontend/src/app/App.tsx: экран диспетчера и состояние приложения.
- frontend/src/features/cameras/Snapshot.tsx: lazy viewport, максимум 4 загрузки, отмена,
  таймаут загрузки/декодирования, backoff, старый кадр до успешной замены.
- AlertPanel.tsx: журнал, принятие, история, opt-in браузерные уведомления.
- CityPanel.tsx: метеопрогноз отдельно от наблюдений камер.

## Текущее состояние

Snapshot повторяет загрузку текущей версии после ошибки через scheduleRetry.
Отмена, очередь и таймауты проверены тестами.

Интерфейс получает статусы и сигналы через `/api/stream/status`. Снимки привязаны к версии кадра из метаданных. При изменениях формата данных сверять обработчики в `app.py` и потребителей в `frontend/src`.

В деталях камеры показан снег на земле по свежей оценке модели. Обледенение требует данных покрытия.
Балл признаков снега и уверенность алгоритма показаны по шкале 0–100. Проценты в почасовом прогнозе относятся к осадкам по данным Яндекс Погоды.

UI упрощён: больше отступов, меньше повторов, служебные данные раскрываются по запросу.
Проверка: 20 frontend-тестов, TypeScript/Vite, nginx/API; браузер 390/768/1440 px.
