# Решения и ограничения

- Коммуникация по-русски. Действовать самостоятельно, не повторять запросы разрешений.
- Все сервисы/проверки стека через Docker Compose. Не имитировать запуск без Engine.
- Работать в endermend, не переписывать main и не делать force push.
- Не удалять данные пользователя. Восстановленные оригиналы хранить отдельно.
- При изменении стека обновлять .gitignore/.dockerignore. Не коммитить .env/токены/БД.
- CI workflow находится в корневом .github/workflows/endermend-ci.yml,
  копия шаблона в teams/endermend/.github/workflows/ci.yml.
- Разделять HTTP-доступность, изменение кадра и достоверность признаков снега.
- Не выдавать CV-score или вероятность всех осадков за откалиброванную вероятность снега.
- Прогноз не подавляет положительное свидетельство с камеры.
- Использовать настроенный серверный ключ Яндекс Погоды. Подключать платный тариф только по поручению пользователя.
- Оценка редкого JPEG используется в карточке камеры. Для индекса и сигналов требуется пригодная видеосерия или валидное свидетельство настроенной модели.
- Не использовать CAPTCHA/bruteforce камер и не рассылать сообщения произвольным адресатам.
- post-commit обновляет только игнорируемый локальный контекст. Не запускает git commit,
  не меняет отслеживаемые файлы и не делает сетевых запросов.
- Сжатие — lossless gzip журнала плюс ограниченный handoff из вручную поддерживаемых
  CURRENT/DECISIONS/RUNBOOK. Это не автоматическая LLM-суммаризация и не изменение
  внутреннего контекста приложения Codex.
