## Архитектура

```text
Браузер → nginx :5173 → статическая React-сборка
                    → /api/* → FastAPI :8000
                                  ├─ фоновые задачи камер
                                  ├─ HTTP JPEG / FFmpeg HLS
                                  ├─ OpenCV-анализ
                                  └─ SQLite в Docker volume
```

- Backend — Python 3.12, FastAPI, Uvicorn, OpenCV, NumPy и httpx.
- Хранилище — встроенный модуль sqlite3, база `/data/history.db`, Docker volume `history`.
- Frontend — React 19, TypeScript 5.7, Vite 6.4.6 по lock-файлу.
- SQLAlchemy и Tailwind из предпочтительного стека исходного задания не использованы.
- nginx — отдельный контейнер. Backend доступен внутри сети Compose.
- Опубликованный вход — `127.0.0.1:5173`.
- SSE передаёт JSON с результатами. Буферизация nginx для API отключена.
- Снимки и резервный polling frontend обновляются каждые десять секунд. Это частота интерфейса, получение кадров у операторов имеет отдельные интервалы.
- HTTP-параллелизм и число одновременных операций получения ограничены четырьмя.
- История очищается от записей старше семи суток.

## Computer Vision

Алгоритм обрабатывает последовательность до 16 кадров. До накопления восьми кадров оценка отсутствует. OpenCV вычисляет межкадровую разность, выделяет изменившиеся пиксели и считает небольшие связные компоненты. Медианное количество компонентов преобразуется в число от 0 до 1. Значение выше 0.5 получает статус `snowing`.

Уверенность вычисляется эвристически из контрастности и числа кадров. Обучение и калибровка на размеченных данных не проводились. Дождь, шум, освещение и движение камеры могут приводить к ошибкам. Optical flow, MOG2/KNN и полноценная фильтрация движения автомобилей в текущем MVP отсутствуют.

Для редких кадров РАН анализ движения отключён, метод обозначается как `snapshot_only`. Такие источники предназначены для просмотра снимков. При ошибке или устаревании оценка становится `unknown`.

Каждый включённый реальный JPEG-источник хотя бы раз вернул декодируемое изображение при проверке. Доступность кадра не гарантирует его актуальность или непрерывную доступность источника.

Публичные каталоги, использованные при исследовании:

- КФ ФИЦ ЕГС РАН — https://kam.emsd.ru/visual-observations/.
- ЩОРС — https://www.shors.ru/kamery/kamera-shchors.
- Камчатка онлайн — https://kam-travel.ru/kamchatka-onlajn/.

На странице РАН указана общедоступная публикация раз в 30 минут. Поэтому интервал запроса этих камер установлен в 1800 секунд, оценка по движению отключена. JPEG ЩОРС запрашиваются раз в 30 секунд. При ошибке источник повторно проверяется через 30 секунд.

`Last-Modified` хранится отдельно от времени получения. Старые файлы показываются со статусом устаревания. Без метки оператора время съёмки не подтверждено.

## Полезные факты

- GitHub Actions обнаруживает workflow в корневом `.github/workflows/`. Поэтому шаблон из каталога команды скопирован в корневой каталог.
- HTTP 200 и доступный HLS-плейлист не подтверждают работоспособность камеры. Требуется декодированный кадр.
- Доступный JPEG может содержать архивный снимок. Время HTTP-получения и дата файла имеют разные значения.
- Снег на земле не подтверждает текущий снегопад. Для анализа падающих частиц нужна достаточно частая последовательность кадров.
- Сетевые таймауты были нестабильными. Часть JPEG отвечала только при повторной попытке.
- UI обновляет снимок через собственный backend. Частота запросов браузера не увеличивает частоту запросов к оператору.
- Данные демо исключаются из сводки реальных камер.
- Отсутствие авторизации GitHub не препятствует локальной разработке и запуску Docker Compose.
