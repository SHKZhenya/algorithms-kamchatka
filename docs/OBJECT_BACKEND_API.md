# Объектный backend

22 ноября 2026. Расширение существующего FastAPI; работает без веб-клиента.
План и аудит: [BACKEND_PLAN_2026-11-22.md](BACKEND_PLAN_2026-11-22.md).
OpenAPI и интерактивный контракт: `/openapi.json`, `/docs`.

## Реестр

| GET | Результат |
| --- | --- |
| `/api/v1/registry/buildings?bbox=w,s,e,n` | Все здания доступного снимка, `building_id`, `entrance_ids`, `entrance_coverage` |
| `/api/v1/registry/objects?kind=entrance&bbox=…` | Входы, остановки, медучреждения, образовательные и экстренные объекты |
| `/api/v1/registry/graph?bbox=…` | Узлы и направленные связи по общим OSM node ID, режимы pedestrian/vehicle |
| `/api/v1/registry/coverage` | Городской охват, пропуски входов, компоненты, источники и хеш импортированного CSV |

`bbox` выбирает пересекающиеся объекты целиком; не обрезает геометрию дороги.
По умолчанию используется существующая область пилота. Для города передайте bbox
из `/api/v1/city/metadata`. `registry/graph` — топологический реестр, не замена
маршрутизатору snowops: допуск техники, живые закрытия и запреты поворотов здесь
не вычисляются. Линии разного уровня и геометрические пересечения без общих узлов
не соединяются. `nearby_only` — кандидат по близости, связи в графе нет.
`foot=no/private`, `access=no/private` исключают пешие кандидаты; отсутствие тега
не доказывает пригодность. Ступени сохраняются отдельным типом пути.

Вход содержит ID здания/входа, роль OSM, категорию здания, координаты, источник,
версию и timestamp OSM при наличии, оценённую внешнюю нормаль фасада и её
происхождение. Связь с фасадом в пределах 3 м — пространственная гипотеза,
`building_link_confidence` явно сообщает это. Направление нормали — от севера
по часовой стрелке, оно не означает известное направление двери.

Все здания представлены в реестре. `entrance_coverage=unknown` и пустой
`entrance_ids` означают неизвестное положение входа, а не отсутствие входа.
Для этих зданий доступна оценка наружной полосы фасада; фиктивные точки входов
не создаются. Полнота относится к доступному снимку OSM и дополнению Overture,
а не к подтверждённой переписи зданий города.

## CSV Данила

Необязательная переменная `CITY_SIM_ENTRANCE_CSV` указывает локальный CSV.
Поддержаны колонки `point_source,entrance_id,building_id,lon,lat,building_type,entrance`.
`building_id` имеет формат `way/123` или `relation/123`. Принимаются только строки
`point_source=osm_node`. Другие строки учитываются как неподтверждённые и пропускаются.
Координаты должны быть конечными, соответствовать известному зданию и находиться
не дальше 5 м от его границы. Порог соответствия исследовательский. Дубликаты OSM ID
не заменяют исходные координаты. Хеш файла входит в ключ кеша реестра.
Импорт не устанавливает полевую достоверность и не соединяет точку с ближайшей дорогой.
Файл `building-entrance-snow.csv` отсутствует в проверенном main Данила; импорт
проверен на тестовом формате, а не на недоступном реальном файле.

## Оценки сценария

Базовый путь: `/api/v1/operations/city/runs/{run_id}`.
Используются готовые расчёты существующего CitySnow, `/api/v1/operations/city/runs`
создаёт их по прежнему контракту.

| GET | Параметры и результат |
| --- | --- |
| `…/assessments` | `bbox`, `kind=all/road/building/entrance/bus_stop/medical/facility`, `frame`, `threshold_cm=20`, `order`, `fragments`, `limit`, `offset` |
| `…/assessment?object_id=osm:node:123` | Оценка одного входа/объекта/здания/дороги и его подтверждённых общим OSM узлом подходов |
| `…/object-weather?object_id=osm:node:123` | Сохранённый погодный контекст конкретного расчёта и кадра |

`frame` — индекс сохранённого накопленного кадра, без него итог сценария.
Отсутствующий кадр даёт 422, неизвестный расчёт/объект 404, незавершённый расчёт
или несовместимая ревизия геоданных 409. Изменившиеся данные требуют нового расчёта.
Геометрии и ID возвращаются в GeoJSON, координаты WGS84 lon/lat.

В `properties` оценки независимы:

- `physical`: модельная толщина **нового** снега в см, взвешенное среднее, максимум,
  P90, протяжённость/площадь превышения, доли по всей и покрытой геометрии,
  проблемные фрагменты, размер ячейки и равномерный погодный baseline.
- `significance`: категория и возможные последствия нарушения доступа; это не снег.
- `quality`: покрытие расчётом, происхождение координат, статус входа и пешей связи,
  отсутствие полевой проверки.
- `reasons`: причины включения и место пропусков данных.

Для линий единица `measure=length_m`, для наружных областей `area_m2`, для точек
`point`. `covered`, `missing`, `above_threshold`, `total` выражены в этой единице.
`above_fraction_total` не считает неизвестную часть чистой; неизвестная часть
отдельно хранится в `missing`. P90 — обратная взвешенная эмпирическая функция
распределения по известной длине/площади. Нули известны, NaN неизвестны.

Линии разделяются во всех пересечениях границ ячеек, включая все звенья
изогнутой линии и повторное прохождение ячейки. На границе двух ячеек линия
относится к восточной/южной ячейке, без двойного счёта. Длины и площади измеряются
в метрической проекции проекта. Интерполяции и искусственной детализации нет.

Здание оценивается по наружной полосе 8 м, вход — по полосе в 1–8 м от фасада
шириной 4 м, точка остановки — по кругу радиусом 5 м. Из областей исключаются
контуры всех известных зданий. Это **экспериментальная геометрическая политика**,
параметры указаны в `geometry_policy`; поле снега уже содержит воздействие
соседней застройки и ветра. Повторного эвристического усиления нет.
`approaches` оценивает только реальные линии с общим OSM узлом. Предполагаемая
полоса перед дверью не объявляется существующим пешеходным проходом.

`order=physical` сортирует по P90 убыванию, затем по полноте покрытия и ID,
неизвестные значения в конце. Полнота разрешает равенство физических оценок,
но не подменяет саму физическую величину.
`order=importance_then_physical` сначала ставит медицинские и экстренные объекты,
затем применяет тот же порядок. Это явная исследовательская политика проверки,
без скрытого суммарного балла. `threshold_cm` настраивается (0–1000 см), нормативом
не является. Для больших выборок `fragments=false` сокращает ответ.
Сортировка рассматривает всю выборку до применения `limit/offset`.

## Погода и ограничения физики

Погодные входы читаются из архива именно этого расчёта, а не из текущего прогноза.
Сохраняются исходные часы, их единицы, valid_at, время получения при наличии,
расстояние и экстраполяция. Расстояние, записанное движком, относится к центру
расчётного тайла; отдельное расстояние к представительной точке объекта доступно,
если известны исходные координаты. Размер ячейки снежного поля не принимается
за разрешение прогноза. Неизвестные источник времени/разрешение остаются null.
Для промежуточного кадра baseline восстанавливается только из накопленных входов
данного кадра, а не из итогового снегопада. Маска baseline совпадает с маской снега.

`modeled_new_snow_accumulation` отличается от старого покрова, свежего снегопада
на входе и фактической доступности. Закреплённый движок Данила `087118ff` суммирует
`выпавший снег × эмпирический пространственный множитель`; состояние старого
покрова, его перенос, плотность, таяние и уборка отсутствуют. Интеграл глубины
не является балансом массы. `actual_accessibility=unknown` сохраняется даже
при малом расчётном снеге. Нужны полевые наблюдения за сопоставимое окно.

Существующие `/objects` и `ranking` в старых ответах сохранены для совместимости.
Старый смешанный индекс и оценка по середине не заменяют `/assessments`.

## Воспроизведение

```sh
python -m unittest discover -s city_sim/tests -v
python -m unittest discover -s tests -v
python -m city_sim.reproduce_object_backend --output out/object-backend --city
```

Нужны зависимости `requirements-city-sim.txt`, закреплённый движок и снимки,
установленные по README_CITY_SIM. Сеть для тестов и воспроизведения не нужна.
`report.json` содержит измеренные времена, `deterministic-report.json` исключает
их для сравнения запусков. Полные поля и входы сохраняются в `citywide/` рядом
с отчётом и доступны существующим API при том же `CITY_SIM_DB`.
