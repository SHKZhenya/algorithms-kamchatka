# Типы и единицы v0.1

| Тип | Семантика |
|---|---|
| `CityProfile` | ID города, IANA-зона, версия графа, EPSG:4326 |
| `RoadEdge` | OSM-способ и два узла, независимые направленные и физические ID, длина в целых метрах, класс, имя, происхождение |
| `ServiceTask` | Одно ориентированное ребро, приоритет, число проходов, окно, требуемая возможность и источник |
| `Vehicle` | Старт/возврат в депо, отдельные скорости чистки и транзита, смена, возможности и сценарный профиль |
| `ScenarioSnapshot` | UTC `as_of`, ID, версии ограничений и тарифа, seed, парк, задания и поправки. SHA-256 от JSON типизированного снимка в порядке полей моделей |
| `VehicleRoute / Action` | Одна последовательность на машину, `deadhead/service/wait/return`, узлы, ID ребра, при сервисе ID задания, целочисленное начало и конец |
| `Plan` | Отпечаток входа, версия адаптера, развёрнутые маршруты, объяснения, показатели, происхождение и результат валидатора |
| `HaulRequest / HaulSolver` | Зарезервирован интерфейс по отпечатку снимка и ID мест погрузки и выгрузки. Ответ текущего среза `not_implemented` |

Действия, окна и смены задаются в секундах от `as_of` и имеют полуоткрытую семантику `[start,end)`. Завершение обслуживания ровно в дедлайн разрешено. GeoJSON дополнительно содержит ISO 8601 UTC. Отображение локального времени использует `CityProfile.timezone`. Геометрия линии в GeoJSON соответствует двум соседним узлам OSM. ID физического сегмента общий для направлений внутри одного OSM way.

Все повторные проходы одного задания поручаются одной машине. Покрытие считается по проходам с требуемым ID задания, дугой и временным окном. Площадь не оценивается без ширины. Статусы `observed`, `official`, `osm`, `assumed`, `synthetic` зарезервированы для provenance. План содержит `null` для неизвестной пропускной способности, риска и фиксированных затрат.

Для вывоза следующая версия должна типизировать запас снега, вместимость кузова и площадки в согласованных единицах, окна загрузки и выгрузки, ресурсы постов, результаты синхронизации и историю загрузок. Для повторного планирования требуется фактическая позиция и входящая дуга каждой машины, завершённые операции и операции в работе.
