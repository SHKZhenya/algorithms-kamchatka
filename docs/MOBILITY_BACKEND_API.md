# Входы, ширины и техника: backend API

22 ноября 2026 года, Камчатка. Расширение существующего FastAPI, без отдельного
сервиса. [Результаты и ограничения](../research/mobility-backend-2026-11-22/REPORT.md).
Предыдущие [объектный](OBJECT_BACKEND_API.md) и [динамический](DYNAMIC_SNOW_API.md)
контракты сохранены. Схемы тел запросов доступны в `/openapi.json`.

## Вероятные фасады

`GET /api/v1/registry/facade-hypotheses?building_id=osm:way:…`

GeoJSON LineString для каждой поддерживаемой стены, включая стены внутренних
дворов. Указываются ранг, исходные признаки, источник `facade-rank-1`, наружная
область оценки и отдельно известные OSM-входы у стены. `ranking_score` — оценка
для сортировки, **не вероятность**; `probability=null`. Первые два фасада
перечислены в `metadata.probable_facade_ids`. Низкое место не доказывает отсутствие
двери. Модель исключает собственные метки здания при обучении для этого запроса.

`entrance_status=hypothesis_not_observed`, `predicted_entrance_count=null`,
`exact_door_coordinates_inferred=false`, `graph_connections_created=false`.
Гипотезы не добавляются в `/registry/objects` и не меняют счётчики реальных входов.
Число дверей и их координаты остаются неизвестными. Модель использует геометрию,
пути и закономерности соседних похожих зданий; серии домов не установлены.

Необязательные `territory_id` и `frame` добавляют массу снега в наружной области
**каждого** фасада: среднее/P90 в кг/м² и покрытие. Сохраняются ID состояния и
срок. Так можно оценивать несколько возможных сторон здания, не выбирая
фиктивную точную дверь. Без территории `frame` недопустим; чужая ревизия — 409,
неизвестное здание/территория/кадр — 404. При отсутствии стены ≥2 м возвращается
пустой набор с явной причиной.

Первый запрос строит признаки городского реестра; результат кешируется на
экземпляр реестра, который меняется после review/изменения входных данных.

## Происхождение ширин

`GET /api/v1/registry/road-widths?bbox=w,s,e,n`

Возвращаются исходные линии и теги OSM, ширина с интервалом, барьеры на узлах,
ограничения и отдельная оценка свободного пространства между зданиями в середине
линии. Последняя — только верхняя граница свободного места, **не ширина дороги**.
Сводные счётчики относятся ко всему снимку, `returned_ways` — к выбранному bbox.

Приоритет источников: явный `width`, затем `est_width`, затем число полос.
Поддержаны метры, десятичная запятая, футы и футы/дюймы. Некорректные или
неоднозначные значения остаются неизвестными, исходная строка сохраняется.
Исследовательские интервалы: `width ±20%`, `est_width ±40%`, для полос —
2,5–3,75 м/полосу. Это **не доверительные интервалы**, измерения или нормативы.
Пешеходным дорожкам ширина из числа полос не назначается. Стандартная ширина
по одному лишь типу highway не подставляется.

`surveyed_widths=0` относится к встроенным источникам. Для собственного измерения
используйте `evidence` следующего запроса. Такие данные действуют только в этом
запросе: API не сохраняет их как новые факты реестра.

## Проверка маршрута конкретной техники

`GET /api/v1/equipment/profiles` — три **сценарных** примера sidewalk/compact/truck.
Они не обозначают реальный городской парк или паспортные характеристики.
Потребитель может передать собственный профиль с источником и статусом
`scenario`, `manufacturer` или `measured`.

`POST /api/v1/equipment/route-assessment` принимает:

- `profile`: габариты, рабочую ширину, боковой запас, радиус поворота, предельный
  модуль уклона, сценарный порог снежного препятствия и пригодность для пеших зон.
- `operation`: `transit` или `clear`. Во втором случае проверяется также рабочая
  ширина и разрешение работы.
- `valid_at`: срок с часовым поясом.
- `legs`: последовательность `{way_id,from_node,to_node}`. Каждый переход обязан
  быть парой соседних узлов указанного OSM way, следующий начинается в конце
  предыдущего. Геометрическое примыкание ребра не создаёт.
- `evidence`: не более одной записи на way, с источником, `kind=survey|scenario`,
  полуоткрытым сроком `[valid_from,valid_to)`, интервалом доступной ширины, уклоном,
  признаками `legal_access`, `work_allowed`, `obstacles_reviewed`; необязательно
  GeoJSON Polygon/MultiPolygon `corridor` в WGS84. Разрешения пользователя не
  отменяют явных противоречащих запретов OSM.
- Необязательные `territory_id`, `frame`, `entrance_id`. Для снежного состояния
  обязательны совпадение ревизии геоданных и **точное совпадение `valid_at`** с
  выбранным кадром. Последний узел сравнивается с реальным OSM-узлом входа;
  близость не считается соединением. Даже при совпадении габариты двери остаются
  неизвестными.

Воспроизводимый пример через Python; реальный ID входа и связи берите из
`/registry/graph` и `/registry/relationships`:

```python
import requests

base = 'http://127.0.0.1:8008'
profile = requests.get(base + '/api/v1/equipment/profiles').json()['profiles'][0]
graph = requests.get(base + '/api/v1/registry/graph').json()
edge = graph['edges'][0]
payload = {
    'profile': profile,
    'valid_at': '2026-01-01T00:00:00Z',
    'operation': 'transit',
    'legs': [{'way_id': edge['way_id'],
              'from_node': edge['from'], 'to_node': edge['to']}],
}
r = requests.post(base + '/api/v1/equipment/route-assessment', json=payload)
r.raise_for_status()
print(r.json()['status'])  # Часто unknown: замеры и разрешения не заданы.
```

Ответ разделяет `geometric`, `legal`, `work`, содержит причины по каждому
переходу, повороты, источники, требуемую и оставшуюся ширину. Сводный статус:
`blocked` при установленном препятствии, иначе `unknown` при любом пробеле,
иначе `passable` **в рамках заданных данных/сценария**. Реальный эксплуатационный
допуск возвращается отдельно как `actual_operational_access=unknown`.

Учитываются ступени, узловые барьеры, физическая и юридическая ширина, высота,
длина, односторонность, доступ, уклон и простые via-node запреты/only-повороты.
Численный уклон понимается в процентах, `°` переводится через тангенс; `up/down`
без числа остаётся неизвестным. Неразобранные масса/осевая нагрузка,
условные ограничения и обнаруженные via-way ограничения требуют проверки.
Неперечисленные локальные и организационные ограничения не считаются проверенными.

Для ненулевого поворота ищется консервативная круговая траектория заданного
радиуса в предоставленных коридорах. Кузов ограничен описанной окружностью;
нехватка места для этой траектории возвращает `unknown`, поскольку другая
траектория не исключена. Проверяются пересечение касательных соседних поворотов
и OSM-запреты. При снеге свободный двумерный манёвр пока не сертифицируется:
результат поворота остаётся `unknown`.

Снежные сечения берутся с шагом ≤1 м (не более 4096 сечений/переход), по каждому
ищется самый длинный непрерывный свободный интервал. Порог высоты переводится
из массы через обе границы плотности. Разрыв данных не принимается за нулевой снег.
Дополнительно проверяется **вся** полоса прямолинейного прохода по всем
пересекающимся ячейкам; широкие, но несвязанные свободные интервалы не дают
`passable`. Исходные значения постоянны внутри ячейки: это не дополнительная
точность растра. Уменьшение ширины и статус рассчитываются из массы после событий,
а не из метки «убрано». Въезд по GPS сам по себе не меняет снег.

## Воспроизведение

```sh
python -m unittest discover -s city_sim/tests
python -m unittest discover -s tests
python -m city_sim.reproduce_mobility_backend --output out/mobility-backend-new
python -m city_sim.reproduce_mobility_backend --output out/mobility-backend-repeat
python -m city_sim.verify_mobility_backend --first out/mobility-backend-new --second out/mobility-backend-repeat --output out/mobility-backend-verification
```

Скрипт работает офлайн с локальным снимком: сохраняет полный реестр ширин,
предсказания независимых блоков, параметры обучения, bootstrap, события,
состояния, сравнение классов техники и контроль массы. ID территории случайный;
`state_id` и численные поля детерминированы. SQLite содержит журнал и кадры.
