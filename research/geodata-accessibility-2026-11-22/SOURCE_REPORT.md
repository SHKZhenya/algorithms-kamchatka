## Основной результат

Получены реальные ответы открытого API ФГИС СКДФ и транспортный GeoParquet
Overture, скачаны и прочитаны три официальных документа ПКГО. Реализован импорт
с происхождением, геометрией поддержки и отдельными категориями сведений.
Канонический граф, production-модель фасадов и UI не изменялись.

Относительно существующего OSM-реестра из 5 914 way:

| Характеристика | Было в OSM | Новых way из СКДФ | Объединённое покрытие way | Новая геометрически покрытая длина |
| --- | ---: | ---: | ---: | ---: |
| Явная численная ширина | 41 | **238** | **279** | **63,724 км** |
| Число полос | 510 | **98** | **608** | **33,520 км** |
| Покрытие | 1 738 | **39** | **1 777** | **15,699 км** |

Ширины СКДФ — **официальные инвентарные/паспортные сведения**, а не подтверждённые
нами свежие полевые измерения. Из 279 way 41 имеют картографическую ширину OSM,
238 — новую сопоставленную паспортную. Это 4,72% всего реестра, не 4,72%
полностью обследованных улиц. Частичное покрытие way учитывается только на
пересечении с исходной поддержкой. Общая поддержка численных ширин — 68,071 км.
Полевых измерений, сделанных или независимо проверенных в этой работе, **0**.

Длины считают объединения поддержек каждого way, а не суммы дублей источников.
Нормализованные Overture- и СКДФ-геометрии не становятся новыми рёбрами графа.
Неизвестные ширины, пешеходные связи и входы не восстанавливаются из факта
близости к данным. Дата наблюдения многих паспортных записей неизвестна.

## Территория и сопоставление

Скачивание Overture охватывает bbox `158.5219917,52.8850294,158.9875423,53.1263189`,
затем отбор делается по полигону OSM `relation/4139922`. В самом OSM эта граница
города помечена условной; её нельзя выдавать за современную кадастровую границу.
Старый расчётный bbox проекта не охватывал её целиком, поэтому для загрузки
использован полный bbox полигона.

Внутри/на границе этого полигона пересекаются 5 861 way существующего снимка,
их обрезанная длина 888,130 км. Общий старый реестр 5 914 way/922,344 км оставлен
знаменателем сравнения с предыдущим отчётом. Число сегментов Overture не равно
числу way OSM: сегментация существенно различается.

Overture сопоставляется по исходному OSM ID, линейным диапазонам и геометрии
с порогом 3 м/80%. Для СКДФ используются название и геометрия с порогом
8 м/80%, для А‑401 также явный route ref. Это исследовательские условия
сопоставления. Они не удостоверяют точность границ покрытия или ширины на местности.
Паспорт автомобильной проезжей части не переносится на параллельную пешую линию.

В файле импорта оставлены 12 неоднозначных записей ширины для разделённых
проезжих частей с `carriageway_assignment_ambiguous=true`; они **не входят**
в прирост покрытия. Отброшены несогласованные геометрии, неполные диапазоны,
неразобранные значения и неподтверждённые привязки. Подробный аудит сохранён в
`out/geodata-accessibility-2026-11-22/import-delivery-verified/results.json`.

## 1. ФГИС СКДФ

Проверены официальный [портал](https://skdf.ru/),
[описание оператора](https://rosdornii.ru/proekty/skdf/) и публичный клиент.
Анонимная версия сайта сама использует `/api/v3/portal` и геометрическую схему
`gis_api_public`. Запросы к этим интерфейсам не требуют логина; закрытые схемы
и токены не использовались. Выполнялись только операции чтения.

Получены 1 414 записей публичного регионального реестра Камчатского края;
из них для подробного сбора выбраны **199 дорог владельца — администрации ПКГО**
(owner ID 2794864) и ещё **24** федеральные/региональные записи, в наименовании
которых есть Петропавловск. Итого **223 карточки, 223 геометрии**, без ошибок
скачивания. Это целевая выборка, а не утверждение о всех частных дворовых проездах.

Название без геометрии оказалось недостаточным: по всему краю 431 запись
совпадает с каким-либо городским именем после нормализации, но среди них есть
одноимённые улицы других поселений. Они не назначались городским way по имени.
После пространственного контроля с существующим графом сопоставлены **106**
паспортных дорог. Прирост ширин для 238 way получен из положительно
локализованных интервалов этих записей.

Явные блоки `roadway` есть у 205 отобранных паспортов: скачаны **216 строк**
с `roadway_width`. Площадь `square` и длина сохраняются для аудита,
**отношение площади к длине не вычисляется как локальная ширина**.
На whole-part геометрию переносится только инвариантное значение, которое
покрывает весь официальный диапазон части дороги.

Показательный источник — [ширины части А‑401](https://xn--d1aluo.xn--p1ai/api/v3/portal/hwm/passports/parts/499564220/roadway):

| Официальный километраж | Паспортная ширина проезжей части |
| --- | ---: |
| 0+000–6+000 | 11,25 м |
| 6+000–13+100 | 14 м |
| 13+100–35+000 | 14 м |
| 35+000–38+000 | 7 м |

Для этой дороги найдены геопривязанные километровые столбы. Меняющиеся интервалы
локализуются только **между** монотонными проверенными опорами на исходной линии;
выполнены проверки близости опор и соответствия геометрической длины километражу.
Экстраполяция и пропорциональное растягивание всей линии не применяются.
Положение между столбами производное, не геодезически измеренная граница.

Получены также:

| Блок | Скачано записей | Что реально известно |
| --- | ---: | --- |
| sidewalks | 663 | У 26 есть `sidewalk_width`, у остальных ширина null |
| barrier-fences | 326 | Инвентарные ограждения с километражом/направлением |
| clearances | 43 | 43 значения габаритной ширины, у 26 — высота при указанном ограничении |
| gabarit | 5 | Весовые/габаритные сведения, в том числе ссылки на временный приказ 2024 года |
| median-separations | 21 | Разделение; разметка не принимается за физическую стену |

Пример тротуарного значения — 2,2 м в записи по Арсеньева. Но сторона и
километраж пока не привязаны надёжно к отдельному пешему way: **прирост
локальных ширин пешеходного графа по этим 26 записям — 0**. Они сохранены
в `contexts` с кандидатом/связанной дорогой и явной неопределённостью, а не потеряны.
Ширина габарита не подменяет ширину проезжей части. Сведения со ссылкой на
ограничение 2024 года не становятся действующим запретом 2026 года.

Права: публичный доступ подтверждён фактическими ответами. Отдельная открытая
лицензия на массовую перепубликацию/коммерческое постоянное использование
выгрузки не установлена. Сырые данные и подключаемый слой оставлены локально;
это не утверждение о разрешении или запрете любого дальнейшего способа использования.
Перед внешней публикацией требуется установить применимые условия оператора.

## 2. Администрация ПКГО

Скачана [КСОДД, 250 страниц](https://pkgo.ru/upload/medialibrary/d1a/d1a47f280e3871b728a1a70a7508f5b5.pdf).
Страницы 31–36 описывают существующую сеть и диагностику 2019–2020 годов;
на странице 32 есть обобщённое описание шести четырёхполосных асфальтобетонных
улиц. Получены кандидаты OSM по названиям, но описание без километража не
разнесено на каждый сегмент. **Новых локальных ширин — 0**.

Из [проекта подъезда к «Спартаку», 154 страницы](https://pkgo.ru/upload/iblock/9ab/9ab0e61a48338f078117c489da699dd2.pdf)
на PDF-странице 11 извлечены проектные 7 м проезжей части, две полосы,
2 м пешеходной части. Там же найдены инженерные материалы и локальные
координаты/контрольные высоты. Они в МСК‑41 и Балтийской системе 1977 года;
проверенного преобразования и геопривязки проектной оси к действующему OSM
нет. Нельзя выдавать эти высоты за готовый DEM у всех входов.

В [газете №633 от 19.01.2018, 96 страниц](https://pkgo.ru/upload/iblock/5d1/5d1bfe39f741c0639bf9376d8ef4e722.pdf),
PDF-страница 51, найдены параметры инвестиционного/реконструкционного объекта:
Чубарова — 7 м, две полосы; Вулканная — 15–18,5 м, 4–5 полос.
Это **проектные характеристики**, а не обследование 2026 года. Напечатанные
в той же таблице экстремальные значения уклона не использованы без проверки
единиц/возможной ошибки документа.

Релевантные страницы визуально сверены после извлечения текста. Проектные
числа сохранены отдельно от паспортных и картографических. Подтверждения
as-built состояния и точной поддержки нет, поэтому прирост локальных
фактических ширин от двух проектных документов **0**. Обнаружение официального
PDF не объявляется общей открытой лицензией на все включённые топоматериалы.

## 3. Overture Maps

[Официальная схема транспортных данных](https://docs.overturemaps.org/guides/transportation/)
и [правила лицензирования](https://docs.overturemaps.org/attribution/) проверены.
Релиз `2026-11-18.0`, транспортная тема ODbL‑1.0. Атрибуция:
**© OpenStreetMap contributors, Overture Maps Foundation**, получено 22.11.2026.

Загружен пространственный срез GeoParquet с сохранением исходных свойств:
из bbox получено 8 730 объектов, полигон города пересекают **7 668 дорожных сегментов**.
Использованы три row group из 128 в соответствующем файле; загружено примерно
24,4 МБ вместо целого 513 МБ файла.

Фактическое заполнение внутри полигона:

- `width_rules`: **49 сегментов, 0,64%**;
- `road_surface`: **2 111**;
- `access_restrictions`: **209**;
- отдельного заполненного поля числа полос в скачанной транспортной схеме нет.

Линейные `between` сохранены. После сопоставления — 46 записей ширин на
41 OSM way, уже имеющем `width`; новых way с шириной **0**. По покрытию
сопоставлены 1 730 way, новых **0**. Поэтому в данном срезе Overture полезен
как нормализованная связанная транспортная геометрия, но **не как независимый
источник дополнительной локальной ширины**. Глобальное наличие поля не означает
его заполненность в городе. Новые GERS/части дорог вне текущего OSM-снимка
не были незаметно добавлены в каноническую топологию.

## 6. 2ГИС и Яндекс

Для 2ГИС **подтверждено существование**
[`items.links.database_entrances`](https://docs.2gis.com/api/search/places/reference/3.0/items/byid).
Документация требует ключ и отдельное разрешение на это поле. Без ключа
официальный запрос вернул HTTP 200, но `meta.code=400` и ошибку параметра key.
Доступных ответов с реальными входами нет; **новых подтверждённых входов — 0**,
потенциальное покрытие неизвестно. Геометрия в контракте может содержать
массивы points/vectors/normals; пример схемы не принят за настоящие координаты.

Проверена [оферта справочного WebAPI, пункт 3.1](https://law.2gis.ru/webapi-offer):
стандартные условия не предусматривают извлечение/сохранение и дальнейшее
использование вне договора, кеширование не предусмотрено. Даже наличие
обычного ключа само по себе не разрешает заполнить постоянный реестр входов.
Для этой цели нужны разрешение поля **и отдельно согласованные права на
выгрузку/хранение/повторное использование**, например соответствующая поставка данных.
Обход ограничений, использование чужих ключей или извлечение из веб-карты не выполнялись.

Для Яндекса проверены
[условия API](https://yandex.ru/legal/maps_api/ru) и
[условия бесплатного использования](https://yandex.ru/dev/commercial/doc/ru/).
Бесплатные условия не дают права один раз получить геокодирование и хранить
его в собственной постоянной базе; расширенные права требуют отдельной проверки.
Подходящего предоставленного ключа/договора и лицензированной дорожной выгрузки
с локальными ширинами нет. Реальных записей не получено, прирост **0**,
покрытие по этим API не объявляется нулевым. Факт доступности публичной карты
не заменяет права на использование её базы.

## Импорт, проверки и оставшиеся пробелы

Работающий слой содержит отдельно `cartographic`, `official_inventory`,
неразрешённые локальные `contexts`, ссылки, источники, исходные диапазоны и
ограничения. API подключается только явно через `CITY_SIM_ROAD_EVIDENCE`.
Старые OSM endpoint и допуск техники не подменяются новым источником молча.
По умолчанию внешний слой выключен; UI не изменён.

**77 тестов города и 9 тестов ядра прошли.** Проверены диапазоны, единицы/числа,
геометрическое сопоставление, запрет ширины из площади, километровые опоры,
отделение тротуаров и контекста, ревизии/ошибки API и неизменность графа.
Контрольные суммы и повторяемость — в [verification.json](verification.json).

Остаются: зимняя доступная ширина, свежесть паспортных обследований, положение
26 тротуарных ширин на конкретных пеших рёбрах, большинство узких дворов,
точная поддержка барьеров/габаритов, инженерные уклоны и лицензированный источник
новых входов. Прирост фактов есть; полнота и эксплуатационный допуск пока не достигнуты.
Сырые данные, слой и расчёты оставлены локально, без публикации и развёртывания.
