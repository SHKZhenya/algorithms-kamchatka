# Алгоритмы Камчатки · 3D город

Интерактивная карта Петропавловска-Камчатского для исследования ветра и переноса снега. MapLibre рисует рельеф, здания, дороги и инфраструктуру. Three.js отрисовывает расчётные поля, когда доступен аэродинамический решатель. FastAPI хранит сохранённые сценарии и записи внешнего решателя в SQLite. Результаты городского расчёта снега сохраняются в файлах серверного тома.

Динамическое состояние снега, ветровой перенос старого запаса и события уборки
реализованы отдельной версией рядом со старым движком:
[API и воспроизведение](docs/DYNAMIC_SNOW_API.md),
[сквозные результаты и покрытие](research/dynamic-backend-2026-11-22/REPORT.md).
Начальное состояние и воздействия требуют явного источника и маркировки сценария;
подтверждение GPS-прохода не подменяет подтверждение уборки.

## Запуск с нуля

Понадобятся Git, запущенный Docker с Compose v2 и интернет для первой сборки. На macOS и Windows подойдёт Docker Desktop.

```sh
git clone --branch main --single-branch https://github.com/SHKZhenya/algorithms-kamchatka.git algorithms-kamchatka-city
cd algorithms-kamchatka-city
docker compose -f compose.city-sim.yml up --build --detach --wait
docker compose -f compose.city-sim.yml ps
```

Откройте [карту](http://127.0.0.1:8008) и [справку API](http://127.0.0.1:8008/docs). В выводе `ps` оба сервиса должны иметь статус `healthy`. Образ API автоматически загружает закреплённую модель Данила и проверяет SHA-256 её файлов. Рельеф и исторические серии входят в репозиторий, база создаётся при первом старте.

Для первого прогона выберите «Выбранный район» и «Исторический циклон», затем нажмите «Рассчитать снег за всю серию». После расчёта перетащите шкалу времени внизу карты и нажмите на точку, чтобы увидеть расчётную глубину снега. Для этого сценария достаточно данных из репозитория, ключ OpenWeather не нужен.

Объектный backend (дороги по всей геометрии, входы и подходы, погода сценария,
раздельные воздействие/значимость/качество) описан в [контракте API](docs/OBJECT_BACKEND_API.md).
Он работает независимо от интерфейса. [Отчёт о пилоте и покрытии города](research/object-backend-2026-11-22/REPORT.md).

В Compose `city-web` обслуживает статику в Nginx и проксирует `/api/`, `/docs` и `/openapi.json` в `city-api`. Веб-порт доступен на компьютере, где запущен Docker. Сценарии и результаты хранятся в томе `city_sim_state`. Для остановки с сохранением данных выполните `docker compose -f compose.city-sim.yml stop`.

Запуск без контейнера на Python 3.12+ из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-city-sim.txt
python -m city_sim
```

## Погодный контроль дорог и карта накопления снега

Экран «Карта снега» связывает область и выбранный срок погоды с расчётом снега. В окне «Дороги для проверки и отчёт» можно перейти к сегменту на карте и скачать результат. Расчёт для выбранного района сравнивает варианты ветра, рельефа и равномерного фона. [Протокол, результаты и воспроизведение](docs/CITY_SIM_OPERATIONS_VALIDATION.md)

В этом же экране «Весь город» запускает сценарий по свежему прогнозу, погодному архиву, историческому циклону или ручным параметрам. На карте доступны погодные сигналы, снег, ветер, расстояние до погодной точки и приоритет проверки сегментов. [Полный городской прогон и погодные источники](docs/CITY_SIM_CITYWIDE_REPLAY.md)

Для запуска напрямую из Python модель Данила устанавливается отдельной командой.

```sh
git init city_sim/.state/danil
git -C city_sim/.state/danil fetch --depth=1 https://github.com/NDaVS/kamcha-snow-sim.git 087118ff9119eaa211fa19e89251b73f232406da
git -C city_sim/.state/danil checkout --detach FETCH_HEAD
```

Локальный Python-процесс принимает путь к закреплённой копии через `CITY_SIM_DANIL`. API сверяет SHA-256 файлов модели и шаблонов. Архив OpenWeather читается из локальных файлов. Исторические эпизоды входят в репозиторий, ручной сценарий также доступен без локального погодного архива.

## Карта и сценарии

1. На сенсорном экране ведите двумя пальцами вверх или вниз, чтобы изменить наклон. Выберите район и приблизьте карту для просмотра 3D-зданий и дуг. Вкладка «Геоданные» позволяет включить уклоны, инфраструктуру и контрольные точки топографического листа.
2. Клик по зданию показывает источник высоты, клик по дороге — направленные ID, длину и доступный оценочный уклон. Клик по рельефу показывает высоту поверхности в EGM2008.
3. Во вкладке «Сценарии ветра» задайте ветер вручную или выберите ближайший доступный срок из архива OpenWeather. Угол отсчитывается по часовой стрелке от севера и задаёт направление, **откуда** приходит ветер. Прямоугольник на карте показывает расчётную область.
4. Сохраните два сценария, например 9 м/с с 90° и 270°. Их можно заново открыть и скачать входной JSON. Параметры и снимок города фиксируются при сохранении.
5. Укажите `CITY_SIM_SOLVER_URL`, когда будет доступен решатель. Кнопка «Рассчитать» становится доступной при настройке адаптера. У завершённых прогонов можно переключаться между давлением и скоростью воздуха, если эти поля вернул решатель.

Погодный адаптер читает существующие `weather_coverage/heatmaps/forecast_frames.csv` и `observations_full.csv`. В Compose папка атласа смонтирована на чтение. Для отдельной выгрузки укажите `CITY_SIM_WEATHER` в окружении процесса или скорректируйте путь монтирования. Прогнозы и ответы Current относятся ко времени в архиве. Выборка берётся из ближайшей точки в радиусе 3 км для каждого срока, без интерполяции. В сценарии сохраняются срок, время получения, идентификатор точки, хеш CSV и ссылка на исходный ответ. Время выпуска `issued_at` остаётся пустым, если его нет в исходных данных.

## Покрытие и точность

- Рельеф собран из двух открытых тайлов Copernicus GLO‑30. Это цифровая модель поверхности с номинальным шагом 30 м и вертикальной системой EGM2008.
- Карта включает 13 914 контуров OSM. Из них 5 584 добавлены из выпуска Overture. Муниципальная этажность и год постройки сопоставлены по адресам. Опциональный исследовательский слой GlobalBuildingAtlas добавляет модельные высоты и контуры для ручной сверки. [Покрытие, качество и подготовка слоя](docs/CITY_SIM_BUILDING_COVERAGE.md)
- Маршрутный слой использует версию графа `osm-1143744836afc553-demo-v1`, 10 567 направленных дуг и 108 точек инфраструктуры. На юге, включая Завойко, видны картографические линии OSM. Покрытие маршрутного графа ограничено исходным исследовательским коридором.
- Для центральной области в API возвращаются 1 077 зданий, 3 009 дуг и 13 объектов инфраструктуры. Уклоны привязаны к существующим ID из зимнего аудита.
- Пять отметок сверены с листом N‑57‑102 масштаба 1:100 000, издание **1990 года**, местность **1987 года**. Метод, результаты и ссылки приведены в [аудите высот](docs/CITY_SIM_HEIGHT_AUDIT.md).

[Контракт решателя и вопросы интеграции](docs/CITY_SIM_SOLVER_CONTRACT.md)

## Тесты

```sh
python -m unittest discover -s city_sim/tests -v
```

CI запускает API-тесты и проверяет образ Docker. Слои OSM распространяются по ODbL. Свойства DEM и хеши оригиналов перечислены в [паспорте рельефа](city_sim/data/terrain.json). MapLibre GL JS 5.6.2 и Three.js 0.179.1 поставляются с лицензиями в `city_sim/web/vendor/`. Команда `python -m city_sim.vendor` повторно извлекает эти версии из архивов с проверкой SHA‑256.

### Работа с погодой на компьютере

Над картой вертикальное движение двух пальцев по трекпаду меняет наклон. С мышью для наклона можно использовать Alt и колесо.

На вкладке «Карта снега» выберите область расчёта и источник погоды. По умолчанию открыт свежий прогноз. Можно рассчитать весь город, окрестность района или свой контур. При выборе своей зоны рисование включается сразу. На карте можно поставить от 3 до 64 точек и завершить контур клавишей Enter или кнопкой «Готово». Над готовой зоной появляются кнопки «Начертить заново» и «Рассчитать». Район строится вокруг погодного якоря в пределах 2,1 км и обрезается берегом и соседними зонами. В локальных расчётах на участке 128 ячеек по стороне. Размер конкретной ячейки указан в карточке по щелчку. Отображение сглажено, численный замер берётся из ячейки.

Погодное поле, стрелки ветра и рассчитанный снег включаются независимо. Справа сверху меню «Слои» даёт быстрый выбор с цветными превью и переключение между заливкой и объёмной поверхностью. Стрелки указывают, куда дует ветер. В карточке стрелки указано метеорологическое направление, откуда он дует. Цветовые шкалы находятся на карте. «Снег» показывает толщину свежего слоя в сантиметрах, «Наносы» показывают положительную разницу с входным снегопадом, «Дороги» показывают индекс проверки. Щелчок по земле или дороге даёт модельное значение. Если дорожная или строительная точка закрыта маской, интерфейс показывает ближайшую доступную ячейку и расстояние до неё.

Нижняя шкала показывает сроки погодного атласа. В исторических сериях можно просмотреть каждый час погоды до расчёта. После расчёта шкала синхронизирует погоду и накопление на контрольных кадрах многодневной серии или на каждом часе свежего прогноза. Свежий прогноз Open-Meteo обновляется каждые 20 минут при открытом разделе. Снег считается на выбранный интервал до шести часов с фиксацией снимка прогноза. Прямому режиму нужен интернет. Данные модельные и почасовые. [Open-Meteo Forecast API](https://open-meteo.com/en/docs)

Для повторного расчёта всех доступных сроков OpenWeather, исторических эпизодов, крайнего срока почасового архива и четырёх ручных контролей используйте `python -m city_sim.reproduce_city_snow --matrix --output out/citywide-weather-final`.

### Обновление прогноза и проигрывание

В свежем прогнозе кнопка «Обновить» запрашивает новую выдачу поставщика. Когда меняется версия входов, расчёт запускается заново, а прежний слой остаётся видимым до появления результата. Повтор той же версии и параметров использует готовый результат. Погодная заливка, дымка и снег плавно переходят между кадрами. Замеры в карточках берутся из вычисленных сроков. Дымку можно включить в меню «Слои» для источников с облачностью.
